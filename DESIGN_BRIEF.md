# Wishka — дизайн-бриф (макеты + прототип)

> Документ для работы в Claude Design. Цель: макеты всех MVP-экранов мобильной версии и кликабельный прототип ключевых флоу.
> Продукт: **Wishka** — mobile-first веб-сервис вишлистов, которыми делятся с близкими. Open source.
> Версия 2 — после ревью: добавлены состояния ошибок, жизненный цикл брони, гостевая механика, управление группами, архив.

---

## 1. Суть продукта в одном абзаце

Wishka заменяет общую заметку в телефоне: каждый ведёт свой список желаний (вставил ссылку на товар — карточка собралась сама), делится им с близкими, а те **бронируют** подарки так, что владелец списка этого не видит — сюрприз сохраняется, а подарки не дублируются. Профили собираются в группы («Семья», «Друзья»), у каждого профиля есть публичные параметры (размеры, вкусы), чтобы можно было придумать подарок и не из списка.

## 2. Брендинг, настроение, языки

- Название: **Wishka** (рус. «Вишка»). Домен wishka.app.
- Настроение: тёплое, личное, с лёгкой игривостью — сервис про подарки и заботу, не про шопинг-агрегатор. Без детскости: пользуются взрослые.
- Иконка/логотип — на усмотрение дизайна (звёздочка желания, ленточка подарка, галочка списка…).
- **Светлая и тёмная тема обязательны** — ключевые экраны в обеих.
- **RU + EN с первого дня.** Язык по умолчанию — по языку браузера. Правила:
  - проверить ключевые экраны на длинных строках (EN может быть на ~30% длиннее);
  - название на карточке — максимум 2 строки + многоточие;
  - счётчики со склонениями («1 желание / 3 желания / 5 желаний»);
  - никакого текста внутри иконок.

## 3. Принципы UX

1. **Mobile first**: базовый вьюпорт 375×812. Технические правила: safe area сверху (нотч) и снизу (home indicator); минимальный тап-таргет 44×44; контраст AA в обеих темах; нижний паддинг списков — чтобы FAB не перекрывал последнюю карточку; bottom sheet не прячется под клавиатурой.
2. **Добавление желания — главный жест.** С любого своего экрана не дальше одного тапа (FAB «+»). Happy path: вставил ссылку → 1–3 секунды → готовая карточка.
3. Навигация — нижний таб-бар + FAB:
   - **Мой список** (главная)
   - **Люди** (внутри два таба: «Группы» и «Мои брони»)
   - **Профиль**
   - FAB «+» — добавить желание. FAB скрыт на чужих списках/карточках и в гостевом режиме — там его место занимает CTA «Создать свой список».
4. Карточки желаний — визуальные: крупное изображение, название, цена с валютой, приоритет. Красиво даже с чужими фото разного качества.
5. **Никаких тупиков**: у каждого состояния (парсинг не сработал, лимит AI, пустой список, битая ссылка) есть понятный следующий шаг.
6. Сквозные паттерны (нарисовать в мини-системе один раз): диалог подтверждения деструктивных действий; тост/снекбар с «Отменить» (undo 5 сек); диалог «Сохранить черновик?» при закрытии формы с несохранёнными данными; кнопка в процессе (спиннер + disabled).

## 4. Роли пользователей

| Роль | Кто это | Что видит/может |
|---|---|---|
| Владелец | Залогиненный на своём списке | CRUD желаний, профиль, группы. **Никогда и нигде не видит брони своих желаний** |
| Друг | Залогиненный на чужом списке | Видит желания (с учётом видимости), бронирует, снимает свою бронь; его брони собраны в «Мои брони» |
| Гость | Открыл список по ссылке без аккаунта | Видит желания «для всех», бронирует, представившись именем (+ email опционально). Мягкий призыв зарегистрироваться, без принуждения |

Сноска: **профиль публичен по умолчанию** — это осознанное решение продукта, выключателя профиля в MVP нет. Приватность регулируется видимостью отдельных желаний.

## 5. Сущность «Желание»

- **Тип**: товар по ссылке / впечатление («поплавать с китами») / услуга («поход к стоматологу») / сертификат. (Тип «удиви меня» обсуждался — в MVP не делаем, v2.)
- Название; ссылка (у товара); изображение (спарсенное / загруженное / AI); описание.
- **Цена**: переключатель «точная / вилка от–до»; **валюта у каждого желания своя** ($, €, ₾, ₽…). На карточке вилка выглядит как «2000–3000 ₾»; без цены — «Цена не указана».
- **Приоритет**: «Очень хочу» / «Было бы приятно» / «Просто идея» — крупный наглядный выбор, не выпадайка.
- **Флаг «Мечта»** — отдельный переключатель рядом с приоритетом (не четвёртый уровень), подсказка: «Дорогая мечта — на неё копят или дарят вскладчину». Визуально выделяется на карточке.
- Категория (Электроника, Одежда, Дом, Хобби, Впечатления… — AI подставляет автоматически, можно поменять).
- Заметки/уточнения (размер, цвет, «брать в чёрном»).
- **Видимость** (шит «Кому видно», см. §6.3).
- **Статус**: активно → забронировано (видно всем, **кроме владельца**) → подарено → архив.

## 6. Экраны MVP

### 6.1 Вход и онбординг

Единый флоу входа по коду (без magic-link-ссылки — код работает, даже если письмо открыли на другом устройстве):

- Экран входа: логотип, 1–2 фразы о продукте, «Войти через Google», поле email → «Получить код». В углу — компактный переключатель RU/EN.
- Состояния: невалидный email; спиннер на кнопке; «Письмо отправлено — проверь почту (и спам)»; ре-отправка по таймеру 60 сек; ошибка отправки («Не получилось отправить письмо — попробуй войти через Google»); отмена/сбой Google OAuth («Не удалось войти через Google — войди по коду на почту»).
- Экран ввода кода (6 цифр): неверный код («Код не подошёл, осталось N попыток»); код просрочен (срок жизни ~15 мин, кнопка «Отправить новый»); исчерпаны попытки («Слишком много попыток — попробуй через 15 минут»); ссылка «Изменить почту».
- Мини-онбординг (1 экран, всё пропускаемо): имя, аватар, базовая валюта (подпись: «подставляется в новые желания, у каждого можно поменять»), **ник** — автоподстановка из имени + живая проверка («свободен» ✓ / «занят — попробуй ilya2» / «недопустимые символы»). Пропустил — ник сгенерируется сам.

### 6.2 Мой список (главная)

- Шапка: аватар/имя, счётчик желаний (архив не считается), иконка **«Поделиться»**, вход в **Архив** (§6.9).
- Фильтры-чипсы: категория, приоритет, тип, «Мечты». Сортировка (приоритет / дата / цена). Поиск (иконка в шапке).
- Сетка карточек в 2 колонки (дизайн может предложить своё). На своей карточке: изображение, название, цена, приоритет, бейдж «Мечта», иконка ограниченной видимости. **Бейджа брони на своих карточках не существует ни в одном состоянии.**
- Состояния экрана: skeleton; пустой список («Вставь ссылку на то, что хочешь — остальное сделаем мы» + кнопка); «под фильтры ничего не нашлось» (нейтральная, не онбординговая иллюстрация + «Сбросить фильтры»); ошибка загрузки («Не получилось загрузить» + «Повторить»); офлайн-плашка сверху; pull-to-refresh; бесконечная прокрутка со скелетоном подгрузки.
- Состояния карточки с асинхронной AI-картинкой: «Рисуем…» (шиммер + подпись) → готово (тост «Картинка готова») / не вышло (плейсхолдер категории + «Повторить» / «Загрузить фото»).

### 6.3 Добавление желания — главный флоу

**Шаг 1 — точка входа** (bottom sheet по FAB), три равноправные опции:
1. Большое поле «Вставь ссылку на товар». Если в буфере обмена URL — подсказка «Добавить ссылку из буфера?» (буфер пуст или не ссылка — блок просто не показывается). Работает в браузере, PWA не требуется.
2. «Добавь словами»: свободный текст («поплавать с китами») → AI собирает карточку-черновик (тип, категория, вилка цены, описание).
3. **«Заполнить вручную»** — сразу форма шага 3 с выбором типа, без парсера и AI.

**Шаг 2 — парсинг** (если ссылка). Состояния:
- Быстрый путь: 1–3 сек, карточка-скелетон «Смотрим, что там…».
- Медленный путь (обход блокировки): до 15 сек; через 5 сек текст меняется на «Магазин отвечает медленно, продолжаем…» и появляется кнопка «Заполнить руками» — ожидание никогда не удерживает.
- Успех → шаг 3. Частично → шаг 3 с подсвеченными пустыми полями.
- Не вышло: спокойный тон «Этот магазин не делится данными — заполним вместе», ручная форма с подставленной ссылкой. Не красная ошибка.
- **Стоп-лист** (Amazon и подобные): ручная форма сразу, без имитации парсинга, с тем же пояснением.
- **Дубликат**: «Это уже есть в твоём списке» + превью существующей карточки + «Открыть её» / «Всё равно добавить».
- Шит можно закрыть, не потеряв черновик (диалог «Сохранить черновик?», возврат к нему из FAB-шита).

**Шаг 3 — форма карточки** (одна для всех сценариев):
- Поля из §5. Изображение — три источника:
  - спарсено (превью + «Заменить»);
  - загрузить своё: галерея/камера → «Готовим фото…» (сжатие на устройстве) → превью. Ошибки «Файл слишком большой», «Это не картинка» — не блокируют сохранение;
  - **«Сгенерировать (AI)»** — по явной кнопке, рядом счётчик «Осталось N генераций сегодня»; генерация асинхронная (~20 сек): желание можно сохранить сразу, картинка догрузится (состояния — в §6.2). Лимит исчерпан → кнопка disabled с подписью «AI-лимит на сегодня исчерпан — загрузи своё фото».
- AI-подсказки описания и цены: показывается вариант → «Принять» / редактировать. Ошибка AI («Не получилось — попробовать ещё раз / заполнить руками»). **Никакая AI-ошибка или лимит не блокирует сохранение.**
- Цена: переключатель «точная / вилка», выбор валюты — шит со списком и поиском, сверху базовая и недавние.
- **Видимость — шит «Кому видно»**: «Всем» (по умолчанию) / «Группам» (мои группы с чекбоксами) / «Отдельным людям» (поиск по участникам моих групп; закреплённый партнёр — первым). Групп ещё нет → доступны «Всем» и «Отдельным людям» + ссылка «Создать группу». Правило: если видимость сузили после чьей-то брони — бронь сохраняется, даритель теряет доступ к списку и получает письмо.
- Кнопка «Добавить в список» неактивна только пока пусто название; никакое другое поле сохранение не блокирует.

### 6.4 Карточка желания (детальный экран)

**Своя**: просмотр + редактирование; смена статуса; удаление (подтверждение + undo-тост 5 сек).
- «Уже подарили» → архив. Поле «кто подарил» (опционально): свободный ввод или выбор из участников моих групп. **Никогда не подставляется из бронирований и ничем про них не намекает** — на экранах владельца нет ни одного элемента, зависящего от наличия брони. Дарителю после этого уходит письмо «Твой подарок отмечен как вручённый».
- Если владелец редактирует/удаляет/архивирует забронированное желание — он не видит никаких предупреждений (иначе бронь раскрыта). Что видит даритель — см. «Мои брони» (§6.7).

**Чужая (друг/гость)**: изображение, описание, цена, заметки, «Открыть в магазине», кнопка **«Забронирую»** → подтверждение «Никому не скажем 😉» → бейдж «Забронировано вами».
- Снятие брони: «Снять бронь» → «Желание снова станет свободным для других» → тост «Бронь снята» с «Отменить».
- Забронировано другим: бейдж «Забронировано», кнопки нет, призыв «Посмотреть, что ещё свободно».
- Конфликты: тапнул «Забронирую», а уже занято → шит «Увы, это уже забронировали» + «Что ещё свободно»; желание удалено владельцем, пока смотрел → «Владелец удалил это желание» + возврат к списку.

### 6.5 Чужой список (= чужой профиль)

**Отдельного экрана чужого профиля нет**: профиль человека и его список — один экран.
- Шапка: аватар, имя, свёрнутый блок «Что важно знать» (публичные параметры: размеры, вкусы, «не дарить»). Параметры не заполнены → блок не показывается вовсе.
- Карточки с бейджами «Свободно / Забронировано / Забронировано вами». Фильтр «Только свободные» (+ его пустое состояние «Всё уже разобрали»).
- Пустой список: «У Маши пока нет желаний» (+ для друга — «загляни в „Что важно знать“»).
- Skeleton и ошибка загрузки — как в §6.2.

**Гостевой режим** (по ссылке, без аккаунта):
- Плашка сверху: «Вы смотрите список Маши» + переключатель RU/EN + «Создать свой список».
- Бронирование: мини-форма «Как вас записать?» (имя обязательно, email опционально — «пришлём напоминание и ссылку для управления бронью»).
- Гостевая идентичность: бронь привязана к этому устройству (токен) + email, если оставлен. Экран успеха: «Готово! Мы запомнили вас на этом устройстве» + предложение оставить email. Возврат по той же ссылке с того же устройства → «Забронировано вами», можно снять. С другого устройства → просто «Забронировано» + подсказка «Это вы бронировали? Откройте ссылку из письма». Письмо-подтверждение содержит ссылку «Управлять бронью» (открывает карточку с правом снять).
- **Гость → пользователь**: точки входа — плашка, экран после брони, письмо. После входа возвращаемся ровно на тот же список. Если по email нашлись гостевые брони → «Нашли 2 ваши брони — перенести в аккаунт?» («Перенести» / «Не сейчас»).

### 6.6 Профиль (свой)

- Шапка: аватар (выбор → кроп → прогресс → ошибка «Файл слишком большой»), имя, ник-ссылка `wishka.app/u/ilya` + «Скопировать». Тап по нику → смена с проверкой уникальности и предупреждением «Старая ссылка перестанет работать».
- Строка статуса: «Профиль открыт по ссылке — его видит любой, кому ты её отправишь» + **«Посмотреть, как видят другие»** — предпросмотр своего списка глазами: Гость / участник конкретной группы / конкретный человек. Баннер «Предпросмотр» + «Выйти». **В предпросмотре брони не показываются никогда.**
- Блок «Партнёр»: закреплённый человек (выбор из участников моих групп) — адресат видимости «только партнёру». Состояния: не задан («Добавить партнёра») / задан (аватар + «Убрать»).
- Публичные параметры: шит «Размеры» (одежда, обувь, кольцо, рост… + «Добавить свой параметр»; незаполненные в чужом профиле не показываются) и шит «Вкусы» (теги-чипсы + отдельный блок «Не дарить»). Не заполнено → в своём профиле призыв «Заполни, чтобы тебе дарили точнее».
- Автосохранение с тостом.
- Настройки: язык (RU/EN), тема (светлая/тёмная/системная), базовая валюта, выход (с подтверждением), «Удалить аккаунт» (подтверждение + пояснение, что произойдёт со списком, группами и чужими бронями).

### 6.7 Люди: Группы и Мои брони

Вкладка «Люди» = два таба.

**Группы**:
- Первый запуск: «Группы — чтобы видеть списки близких в одном месте» + «Создать группу» + «У меня есть приглашение».
- Список групп: карточки «Семья», «Друзья» с аватарками.
- Экран группы: участники сеткой (участник без желаний — «Список пока пуст»), тап → его список (§6.5). Заглушка-место под Secret Santa и события (v2, не рисуем).
- Роли: создатель = админ, остальные участники. Меню группы: переименовать, эмодзи/цвет, ссылка-приглашение, «Покинуть группу»; только админ: «Удалить группу», «Исключить участника». Подтверждения с пояснением: «Желания, видимые только этой группе, станут ей недоступны». Админ уходит → права переходят старейшему участнику (или группа удаляется, если он один).
- Создание: название, эмодзи/цвет → ссылка-приглашение (share sheet).
- Инвайт: экран «Вас позвали в „Семью“» → войти/зарегистрироваться → в группе. Кейсы: уже состоишь («Вы уже в группе» → «Открыть»), приглашение отозвано/истекло («Попросить новую ссылку»).

**Мои брони**:
- Список моих броней по всем спискам: мини-карточка желания + аватар и имя владельца + статус + «Снять бронь».
- Статусы от действий владельца: «Владелец изменил желание» (что именно: цена/название/ссылка); «Желание удалено владельцем»; «Подарок вручён». Об изменениях приходят письма.
- Блок «Недавно просмотренные списки» — чтобы вернуться к списку, открытому когда-то по ссылке.
- Пустое состояние: «Тут появятся подарки, которые ты забронируешь».

### 6.8 Шаринг

Единый bottom sheet «Поделиться». Куда ведёт ссылка:
- **Список** → §6.5.
- **Отдельное желание** → его карточка глазами гостя: шапка «Из списка Маши» + «Посмотреть весь список» + бронирование прямо здесь (нарисовать этот экран).
- **Группа** → это приглашение (= «пригласить в группу», одно действие), ведёт на экран инвайта, требует входа. Публичного просмотра группы в MVP нет.
- Системный share sheet + всегда «Скопировать ссылку» (тост «Скопировано») — фолбэк, если share sheet недоступен. Опционально «Показать QR».
- Шаринг желания с ограниченной видимостью → предупреждение: «Это желание видно не всем, но по прямой ссылке его откроет любой».

### 6.9 Архив (история подарков)

- Вход: из шапки «Моего списка» (не вкладка таб-бара).
- Карточки в приглушённом стиле: изображение, название, дата, «кто подарил» (если указано). Группировка по годам.
- Действия: «Вернуть в список», «Удалить навсегда» (подтверждение).
- Пустое состояние: «Здесь будут подарки, которые тебе уже вручили».

### 6.10 Служебные экраны

Каждый — дружелюбный тон и одно действие:
- «Ссылка недействительна или список удалён» → «Создать свой список».
- «Этот список виден только участникам группы» (залогинен, но нет доступа) → «На главную».
- «Приглашение истекло» → «Попросить новую ссылку».
- «Сессия истекла» → «Войти снова» (после входа возвращаемся туда же).
- Глобальная ошибка/офлайн — см. паттерны §6.2.

## 7. Ключевые флоу для прототипа (кликабельные)

1. **Добавление по ссылке**: FAB → вставка → парсинг (все состояния: быстрый, медленный, частично, не вышло, стоп-лист, дубликат) → форма → карточка в списке.
2. **Бронирование глазами гостя**: ссылка → список → карточка → «Забронирую» → «Как вас записать?» → успех → возврат по ссылке → снятие брони.
3. **Сюрприз-режим — парой экранов**: один и тот же список глазами гостя (бейджи броней) и глазами владельца (никаких броней). Плюс архивация с «кто подарил» без намёков на брони.
4. **Группа**: создание → инвайт-ссылка → экран принятия → список участника → «Мои брони».

## 8. Технические ограничения, влияющие на дизайн

- Парсинг **часто** отдаёт неполные данные или ничего (крупные маркетплейсы закрыты) → состояния «частично»/«не вышло»/«стоп-лист» — норма жизни; ручная форма красивая и быстрая.
- AI-картинка ~15–25 сек → только асинхронный паттерн (§6.2/§6.3). AI-операции платные и лимитированы → всё по явной кнопке, у каждой AI-функции ручная альтернатива, лимиты видимы, ничего не блокирует сохранение.
- Фото товаров разного качества → пропорция изображения карточки фиксированная (предложение: 4:5, cover, нейтральная подложка); набор плейсхолдеров по категориям: Впечатления, Услуги, Сертификат, Электроника, Одежда, Дом, Хобби, Другое.
- Валюта у каждого желания своя; **конвертации нет**, суммарных итогов по списку не рисуем; цена всегда в валюте желания.
- **Никаких денег в интерфейсе**: хостинг бесплатного тарифа запрещает монетизацию — в макетах нет тарифов, Pro, donate, рекламы. Платежи через сервис не проходят: только «Открыть в магазине», никаких «Купить»/«Оплатить»/«Скинуться».

## 9. Вне MVP (не рисуем, но помним)

AI-ассистент подарков, Secret Santa, складчина, события и напоминания, PWA share target, тип «удиви меня». В навигации и на экране группы — место под это, не ломая структуру.

## 10. Ожидаемый результат в Claude Design

1. Макеты всех экранов §6 в светлой и тёмной теме (базовые — в обеих, второстепенные — хотя бы в светлой).
2. Кликабельный прототип флоу §7.
3. Мини-система: палитра, типографика, кнопки/поля/чипсы/bottom sheet, сквозные паттерны (§3.6) и **компонент «карточка желания» с матрицей состояний**:
   - роль: владелец / друг / гость;
   - статус: активно / забронировано другим / забронировано вами / подарено (архив);
   - модификаторы: «Мечта», 3 приоритета, ограниченная видимость, нет изображения (плейсхолдер категории), «рисуем картинку…», ошибка генерации, длинное название (2 строки), цена-вилка, «цена не указана», разные валюты.
   - Правило-инвариант: **у владельца бейджа брони нет ни в одном сочетании**.
4. Набор писем (текст + один общий шаблон): код входа, подтверждение брони гостю, «управлять бронью», приглашение в группу, «владелец изменил/удалил забронированное желание», «подарок отмечен вручённым».
